# GPVKR Bot — модульная версия

Это первая модульная сборка текущего Telegram-бота «Геймпад в кармане». Цель этого этапа — разнести существующий код по файлам без добавления жанров и без намеренного изменения поведения.

## Структура

- `src/index.js` — входная точка Cloudflare Worker: webhook и `/setup`.
- `src/handler.js` — маршрутизация Telegram updates и обработка команд/кнопок.
- `src/shared.js` — общие Telegram-функции, кнопки и стандартные тексты.
- `src/db.js` — создание вспомогательных таблиц и работа с редактируемыми текстами.
- `src/catalog.js` — поиск, список игр, алфавит, CSV-импорт и автоматическая обработка постов канала.
- `src/admins.js` — права доступа, администраторы, справка и меню команд.
- `src/texts.js` — интерфейс редактирования текстов владельцем.
- `wrangler.toml` — конфигурация сборки/развёртывания Cloudflare; значения пока являются заглушками.

## Важно перед подключением

**Не подключай этот архив к рабочему Worker до настройки `wrangler.toml`.** Неизвестны точные имя существующего Worker и ID/имя D1-базы, поэтому они оставлены как `REPLACE_WITH_*`, а не угаданы.

1. В Cloudflare открой существующий Worker и найди его точное имя.
2. Открой привязанную D1-базу и найди её имя и Database ID.
3. Замени все три `REPLACE_WITH_*` в `wrangler.toml`.
4. Убедись, что в Cloudflare у Worker есть binding D1 с именем `DB` — код обращается к `env.DB`.
5. `BOT_TOKEN`, `WEBHOOK_SECRET`, `SETUP_KEY` и `ADMIN_ID` должны оставаться в Cloudflare Secrets/Variables. **Не добавляй их в репозиторий и не присылай в чат.**

## Проверка локально

Нужен Node.js. В корне проекта выполни:

```bash
npm install
npm run check
```

Проверка синтаксиса не заменяет интеграционный тест с Telegram и D1.

## Публикация на GitHub

Создай отдельный репозиторий `gpvkr-bot`. Для публичного исходного кода выбери **Public**. Загрузи содержимое папки проекта в корень репозитория, включая папку `src`, `package.json`, `wrangler.toml` и этот README. Не загружай токены, выгрузку базы данных или файлы с секретами.

## Подключение существующего Worker к GitHub

После загрузки файлов: Cloudflare Dashboard → Workers & Pages → выбери существующий Worker → Settings → Builds → Connect → GitHub → выбери репозиторий и ветку `main`. Перед включением автоматического Deploy проверь имя Worker в `wrangler.toml` и D1 binding. После подключения новый push в выбранную ветку будет запускать сборку/развёртывание.

Сначала сохрани старый `worker.js` и резервную копию данных. Если автоматическая сборка завершится ошибкой, не удаляй текущий Worker или D1: сначала исправь настройки сборки.

## Сборка Cloudflare Workers Builds

- Root directory: `/` (корень репозитория).
- Build command: `npm run check` (проверяет синтаксис модулей).
- Deploy command: `npx wrangler deploy`.
- Branch: `main`.

Перед первым Deploy убедись, что все заглушки в `wrangler.toml` заменены и существующий Worker использует имя binding `DB` для своей D1-базы. Не меняй привязку на другую базу: это может привести к работе бота с пустой базой вместо каталога.

## О лицензии

Публичный репозиторий делает исходный код видимым, но сам по себе не выдаёт другим людям явное разрешение переиспользовать и распространять его. Выберем лицензию отдельно, прежде чем объявлять проект открытым ПО.
